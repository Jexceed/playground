# 小小思考岛 - 推进记录与并行任务计划

这份文档用于后续多 agent 并行推进。它记录当前方案、完成情况、待办任务、分工边界和验收标准。设计原则见 [[小小思考岛-设计规划]]，本文只记录执行状态和下一步施工计划。

## 当前定位

项目不是刷题软件，而是 4 岁孩子和家长共玩的“看图、操作、解释、复述”的思维游戏。当前阶段聚焦两个世界：

- 数字岛：数感、比较、合成分解、加减情境、公平分配。
- 逻辑屋：模式、分类、规则切换、抑制控制、顺序计划、证据推理、空间和类比。

核心体验要求：

- 题目必须有生活场景关联，不能只靠抽象符号或成人理解。
- 难度要递进，尤其是流程题要从 2 步、3 步、4 步、5 步逐渐增加。
- 错误选项要相关，不能无厘头；它们应该代表常见误判、近似关系或次优选择。
- 图卡要完整显示，优先用真实场景图承载线索，避免让低龄孩子读长句文字。
- 每题要能让家长追问“为什么”，而不是只判断对错。

- `voice-lines.json` 和 manifest 差异需要单独报告。

边界：

- 不直接改课程内容，除非是明显格式错误。

验收：

```bash

```

### 第 1 批：巩固当前质量

4. Agent C 做移动端和图片显示回归。

### 第 2 批：建设新任务

优先从 `references/001` 中继续建设这些方向：

- 观察与比较：找不同、找变化、局部整体。
- 空间关系：上下左右、里外、视角变化。
- 规律推理：更复杂但可视化的 AB、AAB、旋转、矩阵。
- 证据推理：强线索、弱线索、排除法。
- 多步计划：桥、整理、上学准备、点心流程。

每个新题组必须满足：

- 有生活场景或清晰视觉承载。
- 错误选项是相关干扰。

### 第 3 批：交互升级

优先升级：

- 桥怎么搭：从单选变为拖拽木板。
- 先做什么：从选缺失步骤变为排序卡片。
- 分类机：从单选变为拖到篮子。
- 证据推理：点选线索，再选择结论。

升级时先做一个题组试点，不要一次重写所有题型。

## 多 agent 交接规则

每个 agent 完成任务时，需要在最终回复里报告：

- 改了哪些文件。
- 新增/修改了多少题或图片。
- 运行了哪些验收命令。
- 是否改变了语音行数。
- 是否需要另一个 agent 接续。

避免冲突：

- 多个 agent 不要同时改 `src/data/games.ts` 的同一段题组。
- 视觉 agent 先只改 `imageGallery.ts` 和 `public/images/`，题目接入由课程 agent 或明确分配者处理。
- 前端 agent 不要顺手重写题目数据。
- 音频 agent 在课程 agent 完成一批题目后再跑。
- QA agent 的脚本改动应尽量独立，避免混入题目改写。
