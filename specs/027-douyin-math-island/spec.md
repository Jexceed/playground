# Feature Specification: 抖音小游戏数字岛首发版

**Feature Branch**: `dev`

**Created**: 2026-08-12

**Status**: Implemented（抖音开发者工具、真机与提审仍待外部验收）

**Input**: User description: “小小思考屋 AppID: tta51dd3a03b67523202。先做第一部分数字岛，其他部分暂不做。”

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 亲子进入数字岛并选择游戏 (Priority: P1)

家长和孩子从抖音打开“小小思考屋”，看到清楚、安静的数字岛首页，并可从数字岛的八个游戏中选择一个开始。首发版不显示尚未迁移的逻辑屋和图形工坊入口，避免形成不可用承诺。

**Why this priority**: 用户必须先能快速理解产品、进入真实可玩的数字活动，数字岛首发版才具备独立价值。

**Independent Test**: 在一台支持的手机上首次打开游戏，确认无需账户、付费或广告即可在三次点击内进入任意数字岛游戏。

**Acceptance Scenarios**:

1. **Given** 用户首次打开小游戏，**When** 启动完成，**Then** 用户看到“小小思考屋”和“数字岛”，并能辨认八个可玩游戏。
2. **Given** 用户位于数字岛首页，**When** 点击任一游戏卡片，**Then** 进入该游戏第一题，并播放或允许重播题目语音。
3. **Given** 逻辑屋和图形工坊尚未迁移，**When** 用户浏览首发版，**Then** 页面不提供这两个区域的不可用入口。

---

### User Story 2 - 孩子完成一轮数字思维练习 (Priority: P1)

孩子通过看图、触摸选择、听语音和查看反馈完成数字岛题目；答错时得到可行动的提示并可再次尝试，答对后可以进入下一题。家长始终能追问“为什么”。

**Why this priority**: 完整题目闭环是产品的核心，不应退化为静态题库或只判断对错的刷题工具。

**Independent Test**: 分别从八个游戏中抽取首题、中间题和末题，完成正确、错误、重试、下一题与完成关卡流程，核对图、题干、选项、答案、反馈和语音一致。

**Acceptance Scenarios**:

1. **Given** 孩子进入一道题，**When** 查看题面并点击语音入口，**Then** 能听到与当前题干和指令一致的普通话语音。
2. **Given** 孩子选择错误答案，**When** 提交判断，**Then** 游戏不给出羞辱性评价，提供具体提示并允许重新选择。
3. **Given** 孩子选择正确答案，**When** 提交判断，**Then** 游戏解释为什么正确，记录本题完成，并允许进入下一题。
4. **Given** 一道题包含场景图、分组图卡或时钟，**When** 题面出现，**Then** 视觉线索与题干、答案和反馈指向同一数量关系或时间关系。

---

### User Story 3 - 下次继续上次进度 (Priority: P2)

家长和孩子退出后再次打开小游戏，可以看到已完成题目，并从上次所在的数字岛游戏和题目附近继续，而不必重新开始全部内容。

**Why this priority**: 数字岛包含多个游戏和大量题目；可靠的本地进度能支持家庭分多次共玩。

**Independent Test**: 完成若干题后关闭小游戏，再次打开并选择继续，核对最近游戏、题号和完成状态均恢复；清除小游戏数据后则回到首次使用状态。

**Acceptance Scenarios**:

1. **Given** 用户完成至少一道题并离开，**When** 再次打开，**Then** 已完成状态仍保留，并能继续最近的数字岛位置。
2. **Given** 本地存档损坏或不存在，**When** 游戏启动，**Then** 游戏使用空进度正常进入，不出现白屏或阻止游玩。

---

### User Story 4 - 家长检查学习目标与追问提示 (Priority: P2)

家长能在游戏卡片或游戏内看到简明学习目标，并在孩子答题后使用家长提示追问孩子的观察、数法或理由。

**Why this priority**: “小小思考屋”定位为亲子共玩，而不是孩子独自刷题；迁移必须保留解释空间。

**Independent Test**: 检查八个游戏的目标与家长提示，并在每类题目的反馈环节确认至少有一条可直接提问孩子的提示。

**Acceptance Scenarios**:

1. **Given** 家长查看任一数字岛游戏，**When** 打开游戏说明或完成题目，**Then** 能看到与该题能力目标一致的家长追问。
2. **Given** 孩子答对，**When** 家长继续互动，**Then** 界面不会只显示分数或奖励，而会保留复述过程或说明理由的机会。

### Edge Cases

- 当屏幕狭长、刘海或系统安全区占用空间时，题干、关键图卡、答案按钮和返回入口不得被遮挡。
- 当本地语音文件缺失、解码失败或被系统中断时，游戏仍可继续答题，并提供可重试的语音入口。
- 当连续快速点击选择、提交或下一题时，只处理一次有效操作，避免跳题或重复记录。
- 当小游戏被切到后台再恢复时，当前题目和选择状态保持可理解，音频不会叠加播放。
- 当场景图或图卡加载失败时，游戏显示明确的占位提示，不把缺失视觉当作可作答题目。
- 当用户离线重新进入已下载的内容时，数字岛核心题目、图片、语音与存档仍可使用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 首发小游戏 MUST 只展示和开放数字岛，不展示逻辑屋与图形工坊的入口、进度或内容。
- **FR-002**: 数字岛 MUST 包含现有正式题库中的八个游戏：数一数、一眼看出来、多一点少一点、合起来拆开来、来了又走了、公平分一分、几个几个数、时钟小管家。
- **FR-003**: 每个数字岛游戏 MUST 保留其现有正式题目的题干、指令、难度、视觉线索、选项、答案、成功反馈、重试提示、能力标签和家长提示，除非另有经审核的内容变更规格。
- **FR-004**: 用户 MUST 能从数字岛首页进入任一游戏、返回首页、从头开始、提交答案、错误后重试、正确后进入下一题，并完成整个游戏。
- **FR-005**: 每道题 MUST 在开始时提供题干与指令语音重播；正确和错误反馈 MUST 使用与当前文本一致的本地普通话语音。
- **FR-006**: 数量图卡 MUST 支持一一对应计数、结构化快速识数、左右数量比较、两堆合成、拿走、平均分和成组计数所需的可辨认布局。
- **FR-007**: 时钟题 MUST 清楚区分时针与分针，支持整点、半点和结合生活场景判断 24 小时电子钟时间。
- **FR-008**: 游戏 MUST 在本地保存已完成游戏、已完成题目、能力标签以及最近游玩位置，并在下次打开时恢复。
- **FR-009**: 存档缺失、格式错误或版本不兼容时，游戏 MUST 安全回退到空进度，不阻止启动。
- **FR-010**: 用户答错时 MUST 获得与常见误判相关的具体提示，并可再次作答；不得使用扣时、羞辱、强制广告或付费复活。
- **FR-011**: 游戏 MUST 在主流竖屏手机的安全区域内完整展示核心交互，所有主要触摸目标适合低龄儿童操作。
- **FR-012**: 数字岛核心内容 MUST 不依赖远程服务器才能开始和完成；首发版 MUST 不要求登录、不接广告、不接支付、不收集孩子主动输入的信息。
- **FR-013**: 小游戏 MUST 提供平台要求的侧边栏复访入口，并在不影响儿童题面理解的家长可控位置呈现。
- **FR-014**: 小游戏名称、图标、启动画面、首页、题目页和完成反馈 MUST 使用统一的“小小思考屋”品牌表达。
- **FR-015**: 所有随包或按需下载的运行时图片和语音 MUST 有可审计清单，且不得包含逻辑屋、图形工坊或源图目录中的非运行时资产。
- **FR-016**: 首发包 MUST 可由已认证的抖音小游戏应用 `tta51dd3a03b67523202` 进行开发预览和测试版本上传。
- **FR-017**: 在完成正式提审前，家长 MUST 能查看适龄说明、隐私说明和玩法介绍；具体后台资质提交由应用主体持有人确认。

### Key Entities

- **数字岛游戏**: 一个独立的数字能力主题，包含名称、目标、难度、能力标签、家长提示和有序题目集合。
- **题目**: 一次可作答活动，包含题干、指令、视觉线索、选项、答案、反馈、语音和能力标签。
- **游玩进度**: 本地保存的已完成游戏、已完成题目、已练习能力和最近位置。
- **运行时资产**: 数字岛实际引用的品牌图、角色或物品图、场景图及语音文件，以及验证其完整性的清单。
- **平台应用配置**: 将构建产物关联到已认证抖音小游戏应用的非秘密标识和发布设置。

### Asset & Documentation Impact *(mandatory for this project)*

- **Assets**: 新增独立的抖音小游戏运行时资产目录；从 `public/images/brand/`、`public/images/items/`、`public/images/scenes/` 和 `public/audio/voice/` 仅复制数字岛引用项；保留源资产目录不变。
- **Docs**: 新增本功能的 `spec.md`、`plan.md`、`tasks.md` 与抖音构建说明；更新 `docs/CHANGELOG.md`、`docs/TODO.md`、`docs/assets.md` 和必要的部署说明。
- **Audit Coverage**: `pnpm build`、`pnpm audit:curriculum`、语音清单对齐检查、数字岛资产存在性与范围审计、小游戏数据转换测试、小游戏构建产物体积审计，以及抖音开发者工具预览/真机测试记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户在小游戏启动完成后，可在三次点击内进入数字岛任意一个游戏的第一题。
- **SC-002**: 数字岛八个游戏和全部正式题目均可进入并作答，抽查首题、中间题、末题时，题干、视觉、选项、答案、反馈和语音一致率为 100%。
- **SC-003**: 在至少三种常见竖屏尺寸上，100% 的抽查题目无需横向滚动即可看到题干、关键证据和作答控件，主要操作没有被系统安全区遮挡。
- **SC-004**: 正常网络、弱网和断网重启三种条件下，已下载的数字岛核心内容均能完成一局；语音失败不会阻止答题。
- **SC-005**: 完成题目并重启后，已完成状态与最近位置恢复准确率为 100%；损坏存档测试不会造成启动失败。
- **SC-006**: 首次可交互内容在测试手机上于 5 秒内出现，进入题目后的触摸反馈在 200 毫秒内可感知。
- **SC-007**: 发布候选包只包含数字岛运行时内容，逻辑屋、图形工坊和生成源图的运行时引用数量为 0。
- **SC-008**: 至少 5 组真实亲子试玩中，4 组能在无开发者讲解的情况下进入游戏、完成一道题并找到语音重播入口。

## Assumptions

- 首发形态为免费、无广告、无内购的数字岛验证版；商业化另立规格。
- 目标设备以抖音移动端竖屏为主，不包含抖音 PC 小游戏适配。
- 首发版复用当前正式数字岛题库，不在迁移过程中顺带改题或扩题。
- 进度先保存在本机；跨设备云存档、账号体系、排行榜和社交能力不在本期范围。
- 数字岛的所有题目都属于首发迁移范围，不将范围缩小为仅三个试玩关卡。
- 应用主体持有人负责后台身份材料、软著、备案、适龄说明确认和最终发布操作；开发产物负责提供所需截图、说明和测试包。
