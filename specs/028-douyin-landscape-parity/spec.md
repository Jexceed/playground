# Feature Specification: 抖音小游戏横屏同款体验

**Feature Branch**: `dev`

**Created**: 2026-08-13

**Status**: Draft

**Input**: User description: "抖音小游戏要求横屏，并与当前本机版效果保持基本一致。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 横屏进入同款游戏工作台 (Priority: P1)

孩子和家长从抖音打开小游戏后，直接进入横屏数字岛游戏工作台。页面同时呈现左侧关卡、中间题面和右侧辅助信息，整体层级、卡片感、留白和颜色气质与本机版保持基本一致，不再先看到一张纵向欢迎页。

**Why this priority**: 当前竖屏版与已验证的本机体验差异过大，首屏观感和操作结构是本次改造的核心。

**Independent Test**: 在抖音开发者工具使用横屏手机尺寸打开项目，首屏可直接看到三栏完整结构和一道可作答题目，且无需纵向滚动才能开始。

**Acceptance Scenarios**:

1. **Given** 用户首次打开小游戏，**When** 启动完成，**Then** 画面为横屏，并直接显示数字岛关卡、当前题面、题号导航、家长提示和成长记录。
2. **Given** 用户使用常见横屏手机尺寸，**When** 查看首屏，**Then** 三栏不互相遮挡，主问题、视觉线索、选项和检查按钮均可见。
3. **Given** 用户将本机版与抖音版并排比较，**When** 检查布局层级，**Then** 品牌区、左侧游戏导航、中央答题区、右侧题号和家长辅助区的位置关系一致。

---

### User Story 2 - 在工作台内连续选关作答 (Priority: P2)

孩子可以在左侧切换数字岛的八个游戏，在中间横向选答案并检查，在右侧直接跳转题号；切换时始终保留同一套工作台，不需要返回另一种风格的首页。

**Why this priority**: 同款外观必须建立在可连续使用的导航和作答流程上，而不是一张静态仿制页面。

**Independent Test**: 在同一屏幕内完成“切换游戏—选择题号—听题—选择答案—检查—下一题”，每一步的选中、完成和反馈状态清晰可见。

**Acceptance Scenarios**:

1. **Given** 当前正在作答，**When** 用户点击另一个游戏，**Then** 中央题面切换到该游戏，左侧高亮同步更新。
2. **Given** 当前游戏有多个题目，**When** 用户点击右侧某个题号，**Then** 中央题面直接切到对应题目，当前题号高亮且已完成题号保留完成状态。
3. **Given** 用户已选择答案，**When** 点击“看看对不对”，**Then** 中央区域出现清楚且不遮挡题面的反馈，并允许继续下一题。

---

### User Story 3 - 家长获得同屏陪玩信息 (Priority: P3)

家长无需离开孩子的题面，就能在右侧看到当前题目的追问建议和已积累的能力标签，并能进入家长说明。

**Why this priority**: 小游戏必须保留亲子共玩和追问“为什么”的产品原则。

**Independent Test**: 打开任意一道题，右侧始终可见家长追问与成长记录；答对后能力标签更新，进入说明后可以返回原题。

**Acceptance Scenarios**:

1. **Given** 任意题目已加载，**When** 家长查看右侧，**Then** 可看到与当前题目相关的追问，不必滚动离开题面。
2. **Given** 孩子答对一道新题，**When** 进入下一题或刷新视图，**Then** 右侧成长记录包含该题能力标签。
3. **Given** 家长打开说明页，**When** 返回，**Then** 回到打开前的游戏和题号。

### Edge Cases

- 横屏设备存在刘海、圆角或系统安全区时，三栏和底部操作不能落入不可点击区域。
- 横屏窗口比例比 16:9 更宽或更窄时，中央题面仍应优先获得空间，左右栏保持可读且不覆盖中央内容。
- 一个游戏包含 18 个题号时，题号导航必须完整可达，且当前、已完成、未完成状态可区分。
- 题干、选项或家长提示较长时，文字可换行但不能被裁掉，也不能把核心操作推到首屏之外。
- 没有历史进度时从第一个游戏第一题开始；有历史进度时恢复到最近位置。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 小游戏 MUST 以横屏方向运行，并在项目源配置、构建配置和最终产物中保持一致。
- **FR-002**: 启动后 MUST 直接进入可作答的三栏工作台，不显示独立的竖屏欢迎首页。
- **FR-003**: 左栏 MUST 显示品牌、数字岛概况和八个数学游戏，并清楚标记当前游戏与每个游戏的完成进度。
- **FR-004**: 中栏 MUST 显示当前题号、难度、题干、操作指令、听题入口、视觉线索、横向答案选项、重置与检查/下一题操作。
- **FR-005**: 右栏 MUST 显示全部题号导航、当前题目标记、已完成题目标记、当前家长追问和成长记录。
- **FR-006**: 用户 MUST 能在左栏直接切换八个数学游戏，并在右栏直接跳转当前游戏任意题目。
- **FR-007**: 选项选择、检查、反馈、下一题、重置、听题和听家长提示 MUST 在横屏工作台内正常工作。
- **FR-008**: 用户最近的游戏和题号、已完成题目、能力标签和声音偏好 MUST 继续本地持久化。
- **FR-009**: 家长说明入口 MUST 可达，并在返回时恢复进入前的游戏和题号。
- **FR-010**: 视觉层级 MUST 与本机版保持基本一致，包括浅色网格背景、暖白卡片、柔和边框、金色当前态、蓝绿色题面和大圆角控件。
- **FR-011**: 横屏布局 MUST 适配至少 667×375、844×390、932×430 三类常见可视比例，不发生栏位重叠、关键文字裁切或核心按钮不可达。
- **FR-012**: 本次范围 MUST 继续仅包含数字岛数学内容，不引入逻辑营和图形角。
- **FR-013**: 横屏首屏、导航和主要交互 MUST 通过抖音开发者工具实际编译与可视检查。

### Key Entities *(include if feature involves data)*

- **工作台状态**: 当前游戏、当前题号、已选答案、反馈状态以及是否正在播放语音。
- **游戏进度**: 已完成题目标识、各游戏完成数量、能力标签、最近游戏和最近题号。
- **横屏视口**: 可视宽高、安全区和由此分配的左、中、右栏尺寸。

### Asset & Documentation Impact *(mandatory for this project)*

- **Assets**: 复用现有 `doyingame/assets/resources/images/` 和 `doyingame/assets/resources/audio/`，不新增或搬移图片、语音资产。
- **Docs**: 新增 `specs/028-douyin-landscape-parity/`；更新 `docs/CHANGELOG.md`、`docs/TODO.md` 和必要的抖音平台说明。
- **Audit Coverage**: `pnpm build`、`pnpm audit:curriculum`、`pnpm test:douyin-minigame`、`pnpm audit:douyin-minigame`、`pnpm build:douyin-minigame`、`pnpm test:douyin-minigame:devtools`，并在抖音开发者工具中完成横屏编译与截图验收。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 抖音开发者工具启动后首屏 5 秒内直接呈现一道可作答题目及完整三栏工作台。
- **SC-002**: 在 667×375、844×390、932×430 三类横屏比例中，主问题、线索、全部选项和当前主操作均无需纵向整页滚动即可到达。
- **SC-003**: 与本机版对照的 10 项视觉结构清单中至少 9 项一致：背景、品牌区、游戏导航、题头、题面卡、线索板、横向选项、底部操作、题号网格、家长/成长卡。
- **SC-004**: 八个数字游戏和每个游戏任意题号均可在两次点击内从当前题面到达。
- **SC-005**: 所有既有课程、构建、资源完整性和抖音专项自动验证通过，且构建产物声明横屏方向。

## Assumptions

- 本机版当前运行效果是本次视觉与信息层级的基准，不要求逐像素复制浏览器 CSS。
- 抖音小游戏第一阶段仍只发布数字岛，左栏不会展示尚未迁移的世界入口。
- 目标设备允许用户旋转到横屏；小游戏声明横屏后由平台按横屏窗口运行。
- 现有题库、语音、图片和进度格式可继续使用，不做课程内容变更。
