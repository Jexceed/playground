# 代码图形审查

本记录补充图片文件台账。范围是图形渲染入口和代表状态，不把程序可组合的所有状态计为已逐屏试玩。

| 入口 | 处置 | 核对方式 |
| --- | --- | --- |
| `VisualToken` / `VisualGlyph` | 具体物体、种植动作、分类状态等优先复用已审查 PNG；新增房子、礼物、胡萝卜、种子、水洼等。配对组合也使用这些本地图片。保留作为判断依据的大小、颜色、方向、折线和缺位符号，统一清晰线条。 | `glyphs.json` 的最终 155 个候选种类中，110 个走图片、45 个走 SVG。两页 SVG 联络表均已查看；图片在素材联络表及实际题面中复核。 |
| `VisualComparison` | 数量点改为注册的蓝色圆片；原数量、位置和比较面板保留。 | 数量结构、移一移、守恒、分法、十的关系代表题面和相关回归。 |
| `ActivityTokenArt` 的数量图卡 | 记忆数量使用同一圆片；保留数量和组合结构。 | “谁有几个”第 1、7 题的记忆画面和作答画面。 |
| `GraphInteraction` 的 network 分支 | 新增岛屿贴图、浅水底和有层次的桥面。其他图操作不套用该外观。 | 浏览器第 9 题、原生第 1 题；A–B 单桥变双桥，撤销后仍保留现成桥。 |
| `RulePlayBoards` | 保留 051 的四张精细玩具贴图，移除对公共按钮、选项和题干颜色的覆盖。 | 浏览器计算样式与未定制活动逐项相等；原生示例、翻牌和撤销。 |
| `BridgePlayBoard` / `LogicBridgeChoice` | 保留可辨认的河流、桥板和精确长度关系。无需再添加会遮盖测量信息的纹理。 | “桥怎么搭”代表画面、原有桥交互回归。 |
| 图形工坊、`RectangleExplorer`、`PyramidBoard`、立体投影 | 保留干净的轮廓、交点、格线、面向和遮挡；这些差别本身就是学习线索。 | 所有关联静态图逐图查看，另看图形工坊、矩形、金字塔、立体观察代表页面。 |

`review-glyphs.mjs` 的 `references` 是从题库字符串推导的候选引用，可能包含题目 ID、说明文本或已被新呈现覆盖的旧字段。数字不能解释成实际页面渲染次数或完成覆盖率。例如 `horizontalFold` 的广泛字符串匹配不代表每题都显示折线。

原有 `slowRule`、桥参考符号等旧入口仍可作为兜底存在；当前课程若已有独立情境或交互画面，以实际题面为准。没有把仅含数字、汉字或精确几何的图强行换成生成式插画。
